# 本地向量模型评测

本功能用于比较检索证据，不评判最终生成回答。租户管理员可从“模型 → 向量模型”和“知识库 → 检索评测”进入。

## 先复现一个问题

1. 在“向量模型”添加一个已安装的 Ollama embedding 模型，填写名称、后端可访问的服务地址和完整模型名。无需 API Key。验证会检查 embedding 能力、实际维度及模型 digest。
2. 配置文件里的模型自动显示为只读的“当前配置重算基线”。需要实验查询前缀或运行参数时另建候选配置；编辑配置会产生新版本。
3. 在知识库“快速对比”冻结语料，选 1～3 个模型并输入问题。也可从 chunk 卡片“相似度测试 / 加入评测”开始，仅选当前块或添加干扰块。
4. 对照同一行 chunk 的名次、余弦分数和完整入模文本。未知标签不会自动记作无关；正文含有问题原句也不意味着两端编码输入完全相同。
5. 展开“相关性标注”：2 表示足以回答，1 表示部分相关，0 表示无关或条件不符。困难负例必须为 0，确认审核后可以查看正例领先无关块的分差。
6. 将问题保存到问题集，继续添加经人工确认的同义问法。同一意图不能跨校准与验收分组；完全重复的问题不能充当语言变体。

分数不是正确率，跨模型分数不可作为总榜。“仅当前块”只检查一对文本；要判断模型是否把无关块排在前面，必须包含干扰内容或使用全部有效分块。

## 从校准到交付复测

- 冻结同一份完整语料和问题集版本，人工审核用于计分的候选与已知正确答案。首版精确检索保留至少 Top 10 供 MRR@10 计分；标注未知时不能出具正式通过结论。
- 先运行“调试 / 阈值校准”，分别为每个模型观察正确证据保留率和无答案误召回率。阈值严格采用 `score > threshold`；关闭阈值表示不做分数过滤，并非设为 0。
- 创建“冻结验收”，引用已完成的校准运行，逐个模型选择阈值，在查看验收结果前填写样本量、Hit@5、正确证据保留、无答案误召回和 p95 要求。可再约定困难负例、同义问法和关键问题要求。
- 关键有答案问题必须保留正确证据；关键无答案问题必须不返回候选。不存在一个适用于所有业务的默认合格线。
- “交付链路复测”在独立 HNSW 索引上应用文件/租户过滤、三倍候选预算、有效 chunk 检查与 Top K 截断，同时保存精确检索参照。不同维度和不同模型独立建库。当前 HNSW 复测支持至多 2000 维，较高维度可运行精确评测。
- 浏览“相较基线退化”“困难负例反超”“同组问法部分未命中”“无答案仍返回”等样本，导出 HTML、逐题 CSV 和 JSON 复现清单。

报告结论为“满足已设门槛 / 不满足 / 证据不足”。少量合成用例用于验证功能，不能替代真实业务验收。模型差异按意图组配对统计，样本不足或区间跨零时不宣布候选更好。

## 运行和数据边界

- 新表由 Flyway V21 创建，评测不切换全局 `VectorStore`，不会改写现有知识库向量。新增配置供评测使用，不会自动成为线上索引模型。
- 语料保存完整 `indexContent`；服务禁止静默截断，任何 chunk 编码失败均不能通过丢块获得验收通过。生产复测还要求当前有效语料与冻结快照一致。
- 每次运行保存模型 digest、维度、前缀、运行参数、语料哈希、数据集版本、阈值与环境。运行前后校验模型身份；相同快照和配置可以复用向量缓存。
- 取消运行保留尝试记录；“重试相同输入”创建新运行并沿用冻结输入。服务停止或失联的任务会标记失败，避免永远显示运行中。
- 首版默认最多 10,000 个 chunk、1,000 个问题、3 个模型；快速对比最多 20 题。超限明确报错，不自动采样。后台按模型串行执行，避免同服务模型争抢内存。
- 文件从知识库移除后，相关快照和报告按当前权限拒绝读取；所有 API 和后台任务均校验租户、知识库与管理员身份。
- 存量生产向量没有建库模型 digest，因此“当前配置重算基线”不能被视为历史索引身份已验证。用户提供的 0.56 / 0.54 尚需原始问题、完整块和历史检索记录才能做根因判断。

可选服务端参数：`embedding-evaluation.max-chunks`、`embedding-evaluation.queue-capacity` 和 `embedding-evaluation.production-ef-search`。默认 `ef_search=40`；生产复测应使用实际部署目标参数。小语料下 PostgreSQL 可能选择顺序扫描；部署验收应按目标语料规模检查查询计划。
