# PRD: StarSeaKnow 智能体工作台

> Last updated: 2026-09-03 · Status: 核心工作台已实现，本地验收完成；待生产部署与真实厂商配置验收。

## TL;DR

StarSeaKnow 智能体工作台是企业 / 团队自托管的 LLM 智能体管理界面，覆盖「智能体列表 → 编辑器（配置 + 调试）→ 厂商与模型管理」三个视图。核心场景是**业务人员配置一个 RAG 智能体 → 在右侧多会话调试 → 一键发布快照上线**。本次产品形态升级从「基础资料 + 知识库关联 + 简单调试」改为接近 Dify / MaxKB 的「提示词工作台 + 多会话调试 + 快照版本」混合工作台，**坚持 StarSeaKnow 私有部署定位、保留 sea 视觉主题**。HTML 原型（v14）已定稿，本 PRD 的所有功能与状态以原型为唯一视觉与交互参考。

> 关于 `product-requirements.md`：本轮**未**单独生成（按用户指示跳过 product-discovery）。本文 § Features / § States 全部直接反推自 HTML 原型。

## Target User

企业内部 / 团队内的「租户管理员配置者 + 客服 / HR / IT 等普通成员使用方」。租户管理员不写代码，但需要直接编辑提示词、关联知识库、调试对话；普通成员只查看和使用已发布智能体。他们已经在用 Notion / ChatGPT，对 Dify / MaxKB 类工作台有基础认知，但希望保留 StarSeaKnow 的私有部署属性与 sea 视觉主题。

## Core Scenario

**「HR 同事 5 分钟内把《新员工手册》接进系统，得到一个能回答『试用期年假 / 五险一金 / 电脑申请』的智能体，并立即调试到满意再发布给团队。」** 端到端：列表 → 新建 / 进入 → 填基础资料 → 关联 KB → 写系统提示词（带 `{{user.role}}` 变量）→ 右侧多会话调试 → 满意后「发布 vN」。

## Product Surface（页面与视图）

按 HTML 原型的 body class 切换，三个**互斥视图**通过左下 segmented control 切换（不在顶部）。

| 视图 | body class | 主要内容 | 入口 |
|---|---|---|---|
| 智能体列表 | `show-list`（默认） | metric 行 + tag 搜索 + filter pills + 卡片网格 | 应用启动默认页 |
| 智能体编辑器 | `show-editor` | 左配置侧栏 + 右调试舞台（多会话 / 提示词 / 快照三 Tab） | 点击列表卡片 |
| 模型管理 | `show-models` | 厂商侧栏 + 厂商详情表 | 左下分段「模型」按钮 |

共享壳：64px 左侧窄导航（深底 + sea-sand logo + 5 个图标入口 + 底部头像）+ 主区域；顶部 52px top bar（面包屑 + 标题 + 右上 segmented 视图切换 + 头像）。

## Out of Scope

- **工作流画布（节点拖拽）**：Dify 核心，MaxKB 缺失。StarSeaKnow 90% 场景是 RAG 问答，画布 over-spec。留到 v2+。
- **插件市场 / MCP Server**：与私有部署定位不匹配。
- **批量测试 / 灰度发布 / A/B 实验**：超出当前用户体量。
- **调试会话与消息持久化**：v1 不建立 `debug_session` / `debug_message` 表，不提供历史会话恢复；多会话与消息仅按 `debugContextId` 短暂保存在单机 Caffeine，30 分钟无操作、刷新、离开页面或服务重启后不可恢复。
- **真正的混合检索**：首版「混合检索」开关仅为前端占位，后端继续执行 pgvector 向量检索，不增加关键词召回、RRF、OpenSearch 或 Elasticsearch。
- **多租户 / 成员管理 UI**：后端已有租户成员能力，但本工作台编辑器顶栏只显示「最近编辑」+「发布人」。
- **变量 / 知识库片段的「块插入」到提示词**：HTML 原型 JS 注释明确「未来不再扩展」（line 2219），v1 仅做 5 个固定 snippet。
- **模板市场（3 个模板除外）**：第一版只列「客服 / 运营 / 研发」3 个候选模板入口，模板详情页留到 v2。
- **彩色卡 / 玻璃拟态 / 霓虹色 / emoji 图标**：sea 主题偏冷 + 轻，原型只用文字符号（⌕ ▾ ▦ ⌫ ◷ ▌ ⋯），全部不引入。

## Design Constraints

实现必须严格沿用 sea 主题，**不要**引入新品牌色或字体。完整 token 见 style-guide.md，本节是实现层硬约束。

- Primary: `--sea-signal` `#00A6A6`（青绿，**禁止** Dify 蓝紫或 #3370ff）
- Ink / deep: `--sea-deep` `#11243B` / `--sea-ink` `#19304A`
- Mist / paper: `--sea-mist` `#EAF1F5` / `--sea-paper` `#FCFDFC`
- 强调 / 警示: `--sea-sand` `#E9C98B`（**仅**「运行 / 保存 / 发布 / 添加模型」+ 「有暂存」chip 用）
- 错误: `--sea-danger` `#C8524E`（删除按钮文字色）
- 标题: `Noto Serif SC` 600/700（h1 `clamp(27px, 2.4vw, 32px)`、h2 20px、modal h3 23px）
- UI: `Noto Sans SC` 400/500/600/700（正文 13/14px、辅助 12/11px）
- Mono: `JetBrains Mono`（变量 / 模型 ID / prompt / code / 数字字段）
- Eyebrow: 10px / weight 800 / letter-spacing .16em / sea-signal 颜色（顶部小标识）
- 招牌组件 `.workspace-panel`（=原型 `.panel`）：1px `#d5e1e6` 边 + 12px 圆角 + `0 8px 28px rgb(17 36 59 / 7%)` 阴影 + sea-paper 底——编辑器主面板 / 列表容器 / 模态头都沿用
- 圆角: 6/8 (按钮 + input + 小卡) — 10/11/12 (面板 + 智能体卡) — 999 (chip + filter pill + 状态徽章)
- 阴影: 全部用 `color-mix(in srgb, var(--sea-deep) X%, transparent)` 模式，不用固定 rgba
- Z-index: 普通 modal 100 / 嵌套 modal 110 / Element Plus dialog 2000+
- 间距: 4 的倍数 + 7/9 调整；卡片 padding 14/15/16/18/20/24；section 分隔用 border-top + padding-top 而非大 margin

## Differentiation

「**表单为主 + 强提示词 snippet + 多会话调试 + 必发快照**」的轻量混合工作台。Dify 太重（画布 + 插件市场）、MaxKB 太工具化（无画布无模板）、Open WebUI 偏个人 ChatGPT 体验。StarSeaKnow 卡在中间，对 90% 的 RAG 问答场景刚好够用且不臃肿，同时坚持私有部署、保留 sea 视觉主题。

## Key Decisions (and why)

非显然决策，每条都直接影响实现。

| Decision | Choice | Rationale |
|---|---|---|
| 工作台主形态 | 表单 + Tab，**不**做画布 | 用户 90% 场景是 RAG 问答，画布 over-spec；功能密度与留白才能对齐（market-research § Opportunity 1, 5） |
| 编辑器布局 | 双栏（配置 + 调试），**取消中间画布** | v1-v13 试过三栏，中等屏挤压严重；调试侧本身是「画布」（多会话 + 快照），中间段冗余 |
| 系统提示词独立 Tab | 从配置「对话」段拆出来 | 它是企业用户最常改、影响最大的字段，独立 Tab 给足空间（market-research § Opportunity 3） |
| 提示词输入辅助 | 仅 5 个固定 snippet + Jinja-like 变量 | 5 个 snippet 覆盖 80% 写作骨架；不开放块插入避免提示词结构发散（原型 JS line 2219 明确放弃块插入） |
| 变量渲染 | `{{user.role}}` 等 Jinja-like 语法，调试侧不强制填充 | 与 Dify 兼容；调试侧允许「用此 prompt 重跑」而不阻塞业务用户 |
| 调试会话状态 | 单机 Caffeine 临时上下文，不进入数据库 | 每个 Tab 使用一个随机 `debugContextId`；后续仅上传新消息。缓存 30 分钟无操作过期，每用户最多 4 个上下文，并限制轮数、单条长度和总 Token；刷新、离开页面或服务重启后不可恢复 |
| 调试活动元数据 | `agent` 仅记录最后调试人和最后调试时间 | 支持「本周调试」统计与「最近调试」展示；不记录会话 ID、消息正文或多轮上下文 |
| 知识库命中呈现 | 流式答案下方 `<details>` 折叠，显示「本轮召回 N 段 / 最高 0.91 / 来源 KB」 | RAG 场景下「引用可追溯」比答案本身更重要，是审稿 / 合规必要能力 |
| 模型管理独立页 | 不塞在每个 agent 编辑器内 | Base URL + API Key 是一次性维护；放共享页降低重复配置；编辑器里只选择当前租户已配置厂商的候选模型 |
| 厂商与租户配置分表 | 公共 `model_provider_catalog` 与租户 `tenant_model_provider` 分离 | 保持现有 MyBatis 自动租户隔离；查询时由服务层合并公共厂商和当前租户配置，避免公共/租户混表绕过隔离插件 |
| API Key 存储 | AES-256-GCM 密文存入 `tenant_model_provider` | 主密钥由部署环境注入；接口仅返回是否已配置与末四位，快照和日志均不得包含密钥 |
| 模型候选与 Agent 模型 | 厂商候选保存在 `tenant_model_provider.selectable_models`；每个 Agent 独占一条 `agent_model` | 不建立 `tenant_model` 表；`agent.agent_model_id` 唯一引用模型映射，模型参数随 Agent 独立配置 |
| 快照必须显式发布 | 编辑器状态可「有暂存」，但线上只看「已发布 vN」 | 与 Dify 一致：草稿与发布解耦，避免误上生产；快照是回滚与对账的物理证据 |
| 快照保留与回滚 | 快照永久保留；回滚创建新版本 | 历史快照不可变，例如从 v18 回滚到 v12 后创建「v19 · 回滚自 v12」，而不是改写 v12 或 v18 |
| Agent 删除 | Agent、独占 `agent_model` 与全部 `agent_snapshot` 一起软删除 | 厂商连接、知识库和 `agent_knowledge` 关联保留；默认查询与运行入口过滤已删除记录 |
| 权限 | `tenant_admin` 配置、调试、发布与删除；`tenant_member` 仅查看和使用已发布 Agent | 首版沿用现有角色模型，不新增 `agent_editor` |
| 旧模型密钥迁移 | 不迁移 `agent.model_api_key` 明文 | 保留 Agent 业务数据，升级后要求租户重新配置厂商与模型；完成迁移后再分阶段删除旧模型字段 |
| 视图切换位置 | **左下 segmented control**，不在 top bar | 原型明确放在左下；top bar 留给面包屑 + 标题，壳更轻 |
| 顶部窄导航 64px | 不用 Dify 那种 240px 侧导 | sea 主题更轻、信息密度本身不高；保留更多横向空间给三视图切换 + 调试侧 |
| 卡片状态 3 chip | 「已发布 / 有暂存 / 未发布」+ 副 chip「未配置模型」 | 与编辑器顶栏 chip 一致；副 chip 解决「建了但没法跑」的盲区 |
| 列表新建卡 | 虚线 dashed + 「从零开始」+「或选模板」 | 「选模板」是行业标配；第一版先列 3 个候选（客服 / 运营 / 研发），具体模板详情页 v2 |
| tag 搜索 | tag + 词 双模式（空格 / 回车提交） | tag 命中精确但数量有限；自由词兜底常见业务关键词；下方面板给「常用 tag」降低输入成本 |
| 引用折叠 | `<details>` 而非自研 | 浏览器原生、键盘可达、无需 JS 状态；与企业「可打印 / 可截图审稿」契合 |
| 配置侧「系统提示词」4 行入口 | 完整编辑器在右侧 Tab | 配置侧只够「看一眼」，重编辑去右侧 Tab，避免配置侧信息过载 |

## States & Edge Cases

每条都对应 HTML 原型可见的真实状态。

| 元素 | 状态 |
|---|---|
| 智能体卡 | 已发布（sea-signal 圆点）/ 有暂存（sand）/ 未发布（muted） |
| 智能体卡 副 chip | 「未配置模型」当 agent 未关联独占 `agent_model` 时 |
| 列表 filter | 4 个：全部 / 已发布 / 有暂存 / 未发布，互斥 |
| 快照行 | current（色条加粗 + 「· 当前已发布」+ 只显示「预览」）/ 历史（显示「预览 + 回滚」） |
| 快照预览 modal | 状态 chip：当前已发布 / 历史版本；按钮：当前已发布无回滚，历史版本有「回滚到 vN」 |
| 厂商 tab | 8 个，含「ALL」与「自定义」（自定义 count=0） |
| 模型行 | 记录存在即表示可选择；无启用/未启用状态，已被 Agent 使用的模型禁止移除 |
| Tag token | tag（signal-12 浅底）/ 词（不同色）两种样式 |
| 模态关闭 | 点 mask 关闭（`onclick="if(event.target===this) this.style.display='none'"`） |
| 发布校验 | 版本号或简介为空 → `alert` 拦截，不保存 |
| 回滚校验 | confirm 二次确认「将覆盖当前已发布版本，且会基于它创建一条新的已发布记录」 |
| 系统提示词编辑器 | 字符 / 行数实时统计；「还原到上次保存」按钮 |
| 混合检索开关 | 默认开（`switch.on`），仅为前端占位，不保存状态、不改变后端向量检索行为 |
| 调试会话 | 仅短暂存在于单机 Caffeine；关闭 Tab 主动清理，30 分钟无操作、刷新、离开编辑器或服务重启后不可恢复 |
| Agent 删除 | Agent、独占模型配置和全部快照一起软删除；普通列表、详情、调试和正式调用均不可见 |

## Success Criteria

衡量这次升级是否成功的可观察信号。

- 配置者从「打开列表」到「发布第一个 v1」端到端 **≤ 5 分钟**（HR / 业务方可独立完成）
- 调试多会话**支持 4 个单机 Caffeine 临时上下文**；后续请求只上传新消息，刷新页面后不可恢复，数据库和日志中无调试会话或消息记录
- **每个 agent 至少有 1 次快照回滚成功**的端到端 demo（验证发布 / 预览 / 回滚闭环）
- 配置 1 个内置厂商并为 Agent 选择模型 **≤ 1 分钟**（通常仅填写 API Key + 测试连接 + 选择候选模型）
- 视觉一致率：sea 主题 9 个 token 在编辑器所有组件中**全部从 `var(--sea-*)` 读取**，CI / lint 兜底检测
- 反模式零出现：不引入蓝紫 / 玻璃拟态 / emoji 图标（style-guide § 反模式）
- 列表 tag 搜索的双模式（tag + 词）正确分流，候选 tag 点击 + 自由词回车均成 token
