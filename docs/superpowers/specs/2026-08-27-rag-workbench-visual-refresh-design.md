# RAG 工作台视觉重塑设计

**日期：** 2026-08-27  
**范围：** `smart-agent-frontend` 全部用户可见页面  
**目标：** 将现有 Element Plus 默认风格与分散的页面样式，收束为一套面向知识检索与智能体调试的、可访问且响应式的「深海工作台」体验。

## 产品语境与设计主张

本产品服务于维护知识库、配置智能体、验证回答并管理租户的用户。页面的第一任务是让用户快速判断当前所在工作区、下一步操作以及数据状态；视觉不应喧宾夺主。

「深海工作台」借用航标、资料卡和对话信号的意象：克制的墨蓝导航保证方向感，低饱和雾蓝承载信息层次，青色只用于需要行动或正在运行的信号。它避免把 RAG 产品做成聊天机器人皮肤，也避免常见的通用蓝白管理后台。

| 文本 | 岩墨 | `#19304A` | 标题、正文 |
| 文本 | 潮灰 | `#64748B` | 说明、辅助信息 |
| 危险 | 珊瑚 | `#C8524E` | 删除、停用与错误 |

标题采用 `Noto Serif SC`，用于品牌、页标题和认证页主标题；正文采用 `Noto Sans SC`；邀请码、代码与数据标识采用 `JetBrains Mono`。字体通过 CSS 导入并提供系统字体回退。基础字号为 15px，正文行高 1.6，标题层级为 32 / 24 / 18px。

圆角只分三级：控件 8px、普通面板 14px、认证与对话重点面板 20px。阴影仅用于表面从画布中分离，采用墨蓝低透明阴影，禁用浮夸渐变与缩放悬停。

## 结构与页面模板

全局应用壳层在已认证页面中改为左侧工作区导航与右侧画布；小屏幕时导航切换为可横向滚动的顶部栏。认证、受限和邀请落地页不使用此壳层。

```text
┌────────── 深海工作台 ──────────┬─────────────────────────────┐
│ 品牌 / 当前工作区               │ 潮汐线 · 当前模块 / 状态     │
│ ────────────────────────────  │ 页面标题          主操作     │
│ 智能体  知识库  工具            │ ─────────────────────────── │
│ 成员 / 设置（按角色出现）       │ 内容面板 / 卡片 / 表格        │
│ 系统管理（平台管理员）          │                             │
│                                │                             │
└────────────────────────────────┴─────────────────────────────┘
```

1. **实体列表（智能体、知识库）**：统一使用页首（标题、说明、创建按钮）和响应式卡片网格。卡片显示一个低调类别标识、主标题、两行说明、统计/状态及悬停时可见的危险操作；空状态明确提示创建入口。
2. **实体详情（智能体、知识库）**：左侧为可滚动配置面板，右侧为任务区域。智能体预览使用深色会话舱和清晰的来源/发送区分；知识库文档与设置切换为紧凑二级导航并共用表格容器。
3. **工具页**：沿用二级导航，但改为编辑工作台；Markdown 编辑器采用等宽字体、行距与纸面边界，保存操作固定在可见的页尾操作区。
4. **运营页（系统概览、租户、邀请码、成员）**：沿用“运营脉搏”这类真实数据结构，收束为同一表格与筛选面板样式；状态用色和行动按钮保持一致。
5. **认证与邀请页**：使用全高深水背景与一个有航标纹理的单一卡片，清晰区分租户与平台管理员登录入口；表单保持简洁，错误仍由 Element Plus 消息机制呈现。

## 标志性互动

页面内容区顶部放置一条「检索潮汐线」：当前模块以信号青显示，旁有短文本状态点。路由切换时仅让线段作一次 180ms 的宽度过渡；不循环、不装饰性闪烁。此元素同时作为所有页面的共同定位点。

悬停仅用于可点击卡片、导航项和行操作；提供 `:focus-visible` 高对比焦点圈。`prefers-reduced-motion: reduce` 下，所有过渡为零。触控屏不依赖悬停才可发现删除或操作按钮。

## 组件与实现边界

1. `src/style.css` 负责字体导入、令牌、Element Plus 覆盖、可访问性基础和全局响应式规则。
2. `src/App.vue` 负责认证态与应用壳层分流、侧导航、用户菜单和潮汐线；不改变现有路由权限或 API 行为。
3. 页面可新增小型纯展示组件（如 `PageHeader`、`WorkspaceNav`），但不会把业务请求或表单状态迁移出既有视图。
4. 各视图只保留页面专有布局；重复卡片、表格、弹窗、按钮外观迁移至全局令牌或共享组件，消除当前多份 `#409eff`、圆角和阴影定义。
5. 不改动后端接口、鉴权规则、路由地址、数据字段和现有交互文案的业务含义。

## 错误、空状态与响应式

请求错误保留既有信息来源，但统一用页面内错误条说明“发生了什么”和“可以做什么”。没有数据时显示简短描述和唯一主操作；不使用空洞的营销语言。

在 1024px 以下，侧栏缩窄并保留图标和提示；在 720px 以下，应用壳层转为顶部横向导航，卡片网格单列，详情页纵向堆叠，表格保持可水平滚动；弹窗宽度按视口收缩。所有点击目标至少 40px，高对比文本满足 WCAG AA 的可读性目标。

## 验收与验证

1. `npm run build` 成功，现有 `npm test` 全部通过。
2. 通过桌面（1440px）与移动（390px）截图检查：导航、实体列表、智能体详情、知识库详情、工具、系统表格和认证页均无溢出或遮挡。
3. 键盘 Tab 可到达导航、表单、卡片操作与弹窗按钮，并始终有可见焦点。
4. 开启减少动态效果偏好后，潮汐线、卡片与导航不再动画。
5. 手动抽查创建、编辑、删除、上传、聊天发送、登录、注册和租户管理，确认视觉重构未改变业务流程。
