# 租户用户后台重置密码设计

## 目标

为平台管理台增加租户用户密码重置能力。平台管理员执行重置后，目标租户用户下一次使用当前密码登录时必须修改密码；修改成功后永久清除强制状态，后续登录不再显示重置页面。

## 现状与问题

- `app_user` 当前只有 `password_hash`，没有“必须修改密码”状态。
- `/tenant/members/{id}/reset-password` 属于租户管理员，并生成、返回随机临时密码，不符合平台管理台的目标流程。
- 租户登录响应只有访问令牌和用户信息，前端路由守卫只处理平台管理员的初始密码修改。
- 平台管理台目前只有租户列表，没有租户用户列表和用户密码操作。

## 方案

### 数据模型

给 `app_user` 增加 `must_change_password BOOLEAN NOT NULL DEFAULT FALSE`。只有平台管理员重置密码时将其设置为 `TRUE`；不修改当前密码哈希，不生成临时密码。用户完成密码修改后以当前会话清除该标记。

### 平台管理接口

新增平台管理员专用接口：

- `GET /platform/tenants/{tenantId}/users`：查询指定租户用户，响应只包含用户标识、用户名、显示名、角色、状态和强制修改状态，不返回密码哈希。
- `POST /platform/tenants/{tenantId}/users/{userId}/reset-password`：校验用户属于指定租户后设置 `must_change_password=true`，不返回密码。

两个接口均使用 `@RequireRole("platform_admin")`，并在服务端校验租户和用户归属，不能依赖客户端传入租户上下文。

### 租户登录与密码修改

- `POST /auth/login` 成功响应增加 `mustChangePassword`。
- 新增 `POST /auth/change-password`，要求已登录的租户用户提交 `currentPassword`、`newPassword`、`confirmPassword`；校验当前密码和密码强度，更新 BCrypt 哈希并原子清除标记。
- 登录成功后即使标记为真也签发正常租户会话，以便用户完成修改；但服务端在强制状态期间拒绝除修改密码、登出以外的租户业务接口。
- 平台管理员的初始密码修改接口保持现有行为，租户用户使用独立接口和独立状态。

### 前端流程

- 在平台租户管理页面增加查看用户/重置密码入口。点击重置只提示“已要求该用户下次登录修改密码”，不展示临时密码。
- 登录 store 保存 `mustChangePassword`。
- 将现有初始密码页面改造成可区分平台初始密码和租户用户密码重置的页面，租户用户提交 `/auth/change-password`，成功后清除状态并跳转到原目标页或知识库首页。
- 路由守卫对 `mustChangePassword` 生效：租户用户只能访问重置密码页和登出相关流程；平台管理员继续只能进入原有平台初始密码页。
- 只有服务端返回的标志为真时才展示/跳转，完成修改后不会再次弹出。

## 错误与安全边界

- 当前密码错误、用户不存在、用户不属于目标租户、租户不存在或已停用均返回现有认证/业务错误码，不泄露额外账号信息。
- 重置操作不修改用户启用状态，不影响已有会话；强制限制从下一次请求开始生效。
- 任何密码接口均不返回明文密码或哈希；密码使用现有 BCrypt 编码器。
- 重置和修改操作应使用事务/条件更新，避免并发修改覆盖状态。

## 验收标准

1. 非平台管理员调用平台用户列表和重置接口返回无权限。
2. 平台管理员可看到指定租户用户，并成功标记目标用户必须改密。
3. 未被后台重置的用户登录后不跳转改密页。
4. 被后台重置的用户使用原密码登录后被强制跳转改密页，不能访问业务接口。
5. 新密码校验成功后标记清除，刷新/重新登录均不再出现改密页。
6. 错误当前密码、弱密码和不一致确认密码均不能清除标记。
7. 前后端构建与相关测试通过。
