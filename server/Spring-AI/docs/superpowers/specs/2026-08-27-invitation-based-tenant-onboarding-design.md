# 邀请码驱动的租户开户设计

## 背景与目标

本项目通常由单个公司独立部署。系统提供一个初始化时创建的超级管理员账号；超级管理员不预先创建租户，而是创建邀请码。外部用户只能使用有效邀请码注册，注册成功时系统才创建独立租户及该租户的管理员账号。

目标：

- 首次登录的超级管理员必须修改默认密码后才能使用平台管理功能。
- 平台端将“邀请码管理”与“租户管理”分为独立导航 Tab。
- 邀请码具备生效/到期时间、启用/禁用/已使用状态，并只能使用一次。
- 公开注册页只包含邀请码、用户名、密码、确认密码。
- 有效邀请码注册在一个事务中创建租户、租户管理员和邀请码使用记录。
- 租户业务数据继续按 tenant_id 隔离；注册后租户管理员可修改租户名称，平台管理员可维护内部备注。

## 角色与入口

| 角色 | 登录/注册入口 | 权限 |
| --- | --- | --- |
| 超级管理员 | `/login`，选择“平台管理员” | 强制首次改密；创建/禁用邀请码；查看与备注租户；平台运营管理 |
| 租户管理员 | `/register`，使用邀请码注册；之后通过 `/login` 的“租户用户”登录 | 管理本租户资料、名称及原有租户业务数据 |

租户登录采用用户名与密码；用户名在全局唯一，因此不再要求填写租户代码。

## 数据模型

### platform_admin

保留平台管理员表，新增 `must_change_password` 布尔字段。初始化管理员设置为 `true`；成功修改密码后设置为 `false`。

### invitation（独立表）

邀请码不与账号表或租户表合并。字段：

- `id`
- `code`：唯一、随机、不可预测
- `status`：`ACTIVE`、`DISABLED`、`USED`
- `valid_from`、`valid_until`
- `used_at`
- `used_tenant_id`、`used_user_id`
- `created_by`、`create_time`、`update_time`

邀请码在状态为 ACTIVE、当前时间位于有效期内、且尚未使用时可注册。禁用操作只允许作用于未使用的邀请码；使用邀请码时采用行级条件更新/事务保证一次性。

### tenant

新增 `remark` 供平台管理员内部标识；租户名称创建时赋默认值（由注册用户名派生，例如“<用户名> 的工作区”），租户管理员可后续修改名称。

### app_user

新增租户管理员时写入 `tenant_admin` 角色。用户名全局唯一，避免登录时再输入租户代码。

## 服务端行为

### 初始化与首次改密

- 初始超级管理员由 bootstrap 逻辑创建；默认凭据由部署配置提供，禁止在接口响应或页面中展示。
- 平台登录响应包含 `mustChangePassword`。
- 平台管理员处于该状态时，前端路由强制进入修改密码页；后端除改密、登出和会话续期外拒绝平台管理接口。

### 邀请码管理 API

- `GET /platform/invitations`：分页、按状态/有效期筛选。
- `POST /platform/invitations`：创建邀请码，接收生效和失效时间。
- `POST /platform/invitations/{id}/disable`：立即禁用未使用邀请码。

全部要求 `platform_admin`。

### 公开注册 API

- `POST /auth/register`：接收 `inviteCode`、`username`、`password`、`confirmPassword`。
- 校验密码确认、用户名全局唯一、邀请码状态及有效期。
- 在单个事务中创建 tenant、tenant_admin 用户并将邀请码改为 USED、记录创建关系。
- 成功后发放业务会话，使新管理员直接进入租户工作台。

### 租户资料与平台备注

- `PATCH /tenant/profile`：仅当前租户管理员可修改本租户名称。
- `PATCH /platform/tenants/{id}/remark`：仅平台管理员可修改内部备注。
- 备注不会暴露给租户用户。

## 前端信息架构与界面

全局顶部栏保持 64px，所有内容区从其下方开始，避免固定顶栏压住系统页。系统管理使用独立工作台布局：左侧栏包含“运营概览”“租户管理”“邀请码管理”，右侧内容区响应式展示。

### 邀请码管理页

- 统计：可用、即将过期、已使用。
- 独立列表：邀请码、状态、有效期、注册租户、操作。
- 创建弹窗设置有效起止时间；未使用邀请码可二次确认后立即禁用。

### 租户管理页

- 只展示已成功注册产生的租户。
- 平台管理员可筛选、停用及编辑内部备注。
- 不再承担创建邀请码的职责。

### 注册与登录

- `/register`：清晰的四字段注册卡片与邀请码有效性错误提示。
- `/login`：区分租户用户与平台管理员；租户用户仅显示用户名、密码，并提供“使用邀请码注册”的链接。
- 首次平台登录强制跳转改密页。

## 错误与安全

- 对邀请码无效、已禁用、已过期、已使用返回明确但不泄露内部租户数据的业务错误。
- 密码以 BCrypt 存储，接口不返回密码、refresh token 或邀请码以外的凭据。
- 注册事务失败时不得留下部分 tenant 或 app_user 数据。
- 邀请码禁用与使用的竞争由数据库条件更新或锁保证。

## 测试与验收

- 后端：邀请码状态/有效期/一次性、并发使用、注册事务、首次改密权限、用户名登录、租户名称和备注权限。
- 前端：注册确认密码、邀请码错误态、租户/平台登录字段、首次改密路由、邀请码 Tab 创建与禁用确认。
- 验收：超级管理员创建邀请码 → 外部用户注册 → 新租户出现在租户管理 → 该账号登录并仅访问自己的数据；禁用邀请码后注册被拒绝。
