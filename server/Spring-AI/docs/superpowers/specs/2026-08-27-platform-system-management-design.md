# 平台系统管理设计

## 目标

为 `platform_admin` 提供独立的系统管理区，与租户用户的智能体和知识库操作隔离。首个可用闭环是：平台管理员登录、查看租户、创建租户并获得管理员邀请码、停用租户。

## 信息架构

- 概览：租户总数、启用/停用租户数、用户数，以及数据库、向量库、模型服务的可用状态。
- 租户管理：分页列表、按 code/名称/状态筛选、创建租户、复制管理员邀请码、停用租户。
- 审计日志：查询平台登录、租户创建/停用、邀请创建与成员状态变更；支持时间、操作者、租户和事件类型筛选。
- 平台账号：当前管理员信息与修改自身密码；后续增加多管理员管理。
- 系统配置：只展示模型、向量库和密钥配置的脱敏摘要，不在前端修改或返回密钥明文。

## 权限与数据边界

- 所有 `/platform/**` 管理 API 必须使用 `@RequireRole("platform_admin")`。
- 平台令牌只允许进入平台管理路由；租户令牌不能访问平台管理路由。
- 停用租户只改变 `tenant.status`，不得删除用户、知识库或智能体数据；被停用租户的登录和访问在鉴权层拒绝。
- 审计事件只记录必要元数据：事件类型、操作者、租户、时间、来源 IP、用户代理与结果，不记录密码、令牌或 API 密钥。

## API 演进

第一阶段复用并规范现有接口：

- `GET /platform/tenants`
- `POST /platform/tenants`
- `POST /platform/tenants/{id}/disable`

新增：

- `GET /platform/overview`
- `GET /platform/audit-logs`
- `GET /platform/health`
- `GET /platform/profile` 与 `PUT /platform/profile/password`

列表接口采用 `page`、`pageSize`、筛选条件和统一分页响应。健康接口只返回 `UP`、`DEGRADED` 或 `DOWN` 及安全的诊断说明。

## 前端设计

- 新增 `/system` 的平台管理壳与子路由：`overview`、`tenants`、`audit-logs`、`profile`、`health`。
- 平台管理员登录后默认进入概览；租户用户不可见平台导航，直接访问平台路径时跳转 `/403`。
- 租户管理页创建成功后显示一次邀请码，提供复制按钮，并明确提示邀请码有效期。
- API 客户端统一使用 `/api` 代理，避免视图组件直连后端端口。

## 交付阶段

1. 平台概览和租户管理 UI；接入已有租户 API，增加路由角色隔离和分页筛选。
2. 审计表、事件写入与日志查询 UI；把现有 `AuthAuditLogger` 扩展为持久审计。
3. 健康检查、平台账户修改密码和配置摘要。

## 验证

- 后端：平台管理员可访问全部平台 API；租户管理员与普通成员均得到 403；停用租户后访问被拒绝。
- 前端：平台登录后进入概览，创建租户可复制邀请码；租户用户看不到平台入口。
- 集成测试：覆盖平台登录、创建/停用租户、邀请码接受、审计事件与健康降级响应。
